# FlyCheap → TestFlight via Xcode (the GUI path, matches the Apple handoff)

This is the alternative to EAS. Chosen because Miro already ships K9 Pulse this way and the
Apple handoff is built around automatic signing + Xcode Archive.

## ⚠️ The spaces catch (must build from a space-free path)
The repo path contains spaces (`AI Projects/Egyptair Cheap Flights Project`), which breaks React
Native 0.85's native build. So we build from a **space-free copy** generated by:
```bash
rsync -a --delete --exclude node_modules --exclude ios --exclude .expo "<repo>/mobile/" /tmp/fcbuild/
cd /tmp/fcbuild && npm install && npx expo prebuild -p ios --no-install && cd ios && pod install
open /tmp/fcbuild/ios/FlyCheap.xcworkspace
```
`/tmp/fcbuild` is ephemeral (cleared on reboot). For repeatable builds, keep the build copy at a
**permanent space-free path** (e.g. `~/flycheap-build`) and re-`pod install` there after moving (Pods
bake absolute paths, so a copied Pods dir must be regenerated at the new location).

## Archive → TestFlight
1. Open `FlyCheap.xcworkspace` (the `.xcworkspace`, NOT `.xcodeproj`).
2. Destination → **Any iOS Device (arm64)** (Archive is disabled on a simulator target).
3. **FlyCheap** target → **Signing & Capabilities** → **Automatically manage signing**, Team = **`L3NFNQPS55`**
   (add the Apple ID under Xcode ▸ Settings ▸ Accounts if missing). Bundle id = `Miro.k9.flycheap`.
4. **Product ▸ Archive** (~15 min).
5. Organizer → **Distribute App ▸ TestFlight & App Store ▸ Upload** (or save the .ipa and upload via Transporter).
6. Apple processes (~10–30 min) → appears in **TestFlight ▸ Builds** for the "FlyCheap Tracker" app.

## Gotchas
- The ASC app record "FlyCheap Tracker" must use bundle id **`Miro.k9.flycheap`** — same as the project.
- Accept the updated **Apple Developer Program License Agreement** first (account holder) or upload is blocked.
- Entitlements are already set by prebuild: `aps-environment` (push) + `applinks:flycheap.18dn.com` (universal links).
- After the first build, drop the Android signing SHA-256 into `src/app/api/assetlinks/route.ts` for Android App Links.

## EAS alternative (cloud, immune to the spaces issue)
See `04-EAS-BUILD.md`. `eas-cli` is installed locally in `mobile/` (run `./node_modules/.bin/eas …` to avoid
the root-owned `~/.npm` cache). Flow: `eas login` → `eas init` (paste projectId into app.config.ts) → `npm run build:ios`.

## ✅ Archive fix (2026-06-14): iOS deployment target
First archive failed: `AppDelegate.swift: error: compiling for iOS 15.0, but module 'Expo' has a
minimum deployment target of iOS 16.4`. The app target used `$(RECOMMENDED_IPHONEOS_DEPLOYMENT_TARGET)`
(=15.0 on Xcode 26.5) while the Expo pods are 16.4 — the mismatch also surfaced as a misleading
"C function pointer can only be formed from…" error in the Xcode GUI.
**Fix:** `app.config.ts` → `['expo-build-properties', { ios: { deploymentTarget: '16.4' } }]` (durable, survives
prebuild). For an already-generated project, set `IPHONEOS_DEPLOYMENT_TARGET = 16.4` on the app target in
project.pbxproj. Verified: device Release build → `** BUILD SUCCEEDED **`.
